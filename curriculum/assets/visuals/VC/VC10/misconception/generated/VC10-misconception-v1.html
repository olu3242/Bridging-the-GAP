Testing & E2E Verification

Text equivalent and source

Correctly reject this misconception: A passing mocked UI test proves the production persistence path works. A browser test creates a task and sees it in memory, but never reloads. Add a reload and verify the saved task through the real backend, then test that a second user cannot edit it. Record skipped tests as unverified. A mocked or memory-only pass is not production evidence. Skipped checks remain unverified.
